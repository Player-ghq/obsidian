# 同步时序电路设计

## 知识点介绍

同步设计把行为规格转换为公共时钟下的状态转移和输出函数。关键是确定状态需记住哪些信息，并把复位、暂停、输入优先级与异常编码纳入同一个模型。

## 原理讲解与图示

### 状态是必要历史信息的压缩

串行序列检测中，完整输入历史通常无需全部保存；只需保存仍可能参与未来匹配的后缀。若目标序列为模式 P，状态可表示“已接收串的后缀与 P 的某个前缀相同”的匹配程度。

新输入不匹配时，回退目标是仍有效的最长匹配后缀，未必是初态。允许重叠时，刚匹配完成的末尾也可能保留为下一次匹配的开头；不重叠时则按规格清除这部分历史。

### 次态表与激励的连接

选定编码后，每个状态位的目标次态都是输入和现态的布尔函数。D 型直接令 $D_i=Q_i^+$；T 型令 $T_i=Q_i\oplus Q_i^+$；JK 型按该位激励表给出 J、K 的允许值，再分别化简。

JK 的激励无关项表示多种输入都实现同一已规定转移；未用状态表示规格是否规定了该编码的行为，两者不能混淆。

### 复位、使能与功能次态

设 R 为高有效同步复位、E 为高有效使能，R 优先；复位目标为全 0，正常次态函数为 $\mathbf f$：

$$Q_i^+=\overline R\left(\overline E Q_i+E f_i(\mathbf Q,\mathbf X)\right).$$

该式直接表达三种互斥情况：复位、保持、执行功能。若复位目标不是 0，对应位还需加入 $R\,q_{reset,i}$。异步复位不能简单仅放进该同步 D 方程，它还要连接器件的异步控制端。

### 输出时刻是功能的一部分

Mealy 检测输出在某拍的现态与当前输入组合下产生；Moore 输出出现在对应状态区间。将 Mealy 输出再寄存通常会改变有效时刻，不能只把“更稳定”当作等价设计。

若输出寄存器要装入“更新后状态所对应的数据”，其组合数据必须按正确的次态关系计算。直接用现态译码并在同一沿装入，会得到前一位置的数据，形成一拍错位。

### 非法编码与闭环恢复

自恢复规格决定非法编码的次态。若 E=0 要求任何编码保持，则非法编码恢复只在 E=1 时发生。证明设计正确需覆盖正常路径与异常路径，不能只在复位后列出一条合法序列。

## 配套例题

### 例题 13-01｜Moore 检测

设计 Moore 型“110”检测器，允许重叠；在接收末位后的状态区间输出 Z=1，保持一个时钟周期。采用 JK 触发器，初态为未匹配。给出设计全过程与输入 1110110 下的状态、输出序列。

### 例题 13-02｜带暂停的重叠序列检测

设计同步 Mealy 型 10101 检测器，输入 X、采样使能 E、同步复位 R，高有效，公共上升沿。R=1 优先回到未匹配状态且当拍 Z=0；R=0、E=0 时状态保持、Z=0；R=0、E=1 时接收一位 X，允许重叠检测。Z 按沿前状态与当拍输入确定，检测到最后一位时该拍为 1。

1. 给出最少状态数的状态图、状态含义与完整转移条件，并说明状态最小性的依据。
2. 用最少位数的 D 触发器实现，未用编码要求在 R=0、E=1 时下一拍回初态；E=0 时仍保持。
3. 求驱动式和输出式，画出控制优先级与时钟接线。
4. 初态未匹配，R 全程为 0，X 依次为 1、0、1、1、0、1、0、1、0、1，E 依次为 1、1、1、0、1、1、1、1、0、1。列逐拍状态与 Z。
5. 改为 Moore 输出时，定义明确的输出时刻并比较状态和输出延迟，不得默默改变暂停规则。

### 例题 13-03｜ADC握手与数据寄存控制

设计公共上升沿同步控制器。输入 req、busy_adc、done_adc 已同步到该时钟域，ADC 的 12 位 data 在 done_adc=1 的采样沿前后满足建立保持要求。req 是单拍请求，空闲时到达才接受，忙碌期间请求忽略。

控制器接受请求后输出 start=1 恰好一个完整周期；ADC 保证在 start 周期之后进入 busy_adc=1，且在 busy_adc 首次被采到为 1 的那个沿，done_adc 必为 0。此后完成转换才令 done_adc=1，同时 busy_adc=0；done_adc 可保持到下次转换启动时清除。控制器只有见过 busy_adc=1 后才允许接受 done_adc=1，防止旧完成标志被误认。完成时把 data 捕获进输出寄存器，下一状态区间 valid=1 恰好一个周期，然后回空闲。复位 R 高有效同步且最高优先，清除 valid 与数据寄存器。完成后的 valid 周期不接受新请求。

1. 给出 Moore 状态图、状态编码和所有输出条件，明确数据捕获发生在哪个边沿。
2. 求 D 触发器状态驱动函数及数据寄存器装载使能，确保 start、valid 不多持续一拍。
3. 列“done_adc 先为 1、再出现 busy_adc、随后完成”场景的合法输入时序，并证明不会提前输出 valid。
4. 如果 done_adc 不再同步，说明现有逻辑证明遗漏了什么，不要求设计跨时钟域传输方案。
