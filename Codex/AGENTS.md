# Codex 持久记忆区

本目录用于沉淀跨对话仍有复用价值的上下文，而不是保存完整聊天记录。

## 维护规则

当你在工作中了解到值得长期保留的项目进展、人员背景、关键决策、待办事项、常用工作流或可复用想法时，应及时更新本记忆区中对应的 Markdown 文件。

每次开始重要工作会话前，应先快速浏览本文件，再按当前任务需要查阅相关记忆文件。不要为了“完整”而读取整个记忆库。

- `TODO.md`：跨对话需要继续跟进的待办事项。
- `people/`：与协作有关、确有长期价值的人员背景和职责信息。
- `projects/`：项目背景、状态、里程碑和关键决策。
- `agent/`：Codex 的常用工作流、约定和操作偏好。
- `notes/`：不适合归入以上类别、但值得复用的简洁笔记和想法。

## 常用入口

- `people/用户.md`：用户背景、学习基础、运动背景和偏好。
- `projects/长期目标.md`：考研、HYROX 等长期目标及优先级。
- `agent/输出纪律.md`：默认回复风格、信息密度和多步任务规则。
- `agent/工作流约定.md`：记忆读取、写入、收尾和未解决事项记录规则。

## 会话收尾

结束重要工作会话前：

1. 判断本次是否产生了值得长期记录的人员、项目、决策、待办、重复性工作流、项目状态或可复用想法。
2. 如有必要，更新对应的 Markdown 文件。
3. 向用户说明修改了哪些记忆文件；若没有修改，也应明确说明。
4. 将未解决事项记录到 `TODO.md`，或在需要独立追踪时记录到 `agent/open-loops.md`。

## 写入原则

- 不要直接转储完整聊天记录。
- 不要保存密码、密钥、令牌或隐私信息。
- 只记录跨对话仍有价值、以后可能再次用到的信息。
- 更新应简洁、具体、可检查；待办应包含清楚的下一步或完成标准。
- 优先更新已有文件，避免重复、过时或相互矛盾的记录。
- 记忆文件应便于用户查阅、编辑、对比和重复使用。

## 知识库存储决策

- Obsidian 是当前唯一的知识沉淀位置；资料、复盘、洞察、项目记录和长期记忆均写入本 Vault。
- 以后和 Codex 对话中新创建的项目，默认直接放入 `Codex/projects/`；当前 workspace 的 `work/` 和 `outputs/` 只用于临时草稿、实验文件或明确要求的导出物。
- 思源笔记暂时停用，不再新建、同步或更新思源内容。
- 不自动迁移、覆盖或删除思源中的旧内容；如以后恢复使用，需由用户重新确认迁移范围和规则。
